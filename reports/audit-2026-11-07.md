## Highest-priority risks found
1. **Llama is not a trusted member yet.** Its code path catches exceptions and continues; its report begins as `not run`. It is optional in the final preflight. Verify it actually loads and votes before giving it weight.
2. **The final preflight only requires `svc`, `q14v5`, and `deberta`.** Optional members may silently be absent. Logs must be inspected to know the actual ensemble.
3. **External pool is selected by largest mounted text/model table.** The code chooses a pool from Kaggle input and combines it with official train data. We need to record the exact source file, row count, class counts, duplicates, text-length distribution, and provenance before trusting it.
4. **External-pool group IDs are not equivalent to official prompt IDs.** The notebook does not use the pool's group key to split official validation (which is correct), but any pool-level OOF or centering result must not be treated as official prompt-disjoint validation.
5. **SVC OOF uses only 2 GroupKFold folds.** This is a useful diagnostic but high variance. We should compare against repeated prompt-grouped splits and preserve the exact test-like sampling structure when possible.
6. **Prompt-centering / cluster correction is risky.** Inferred clusters must be evaluated using text-only grouping, never oracle prompt IDs. Small test clusters do not contain all 18 model labels, so Hungarian one-to-one assignment is not justified without evidence.
7. **Class offsets and Sinkhorn are separate post-processing changes.** Each must be validated on honest OOF predictions and ablated independently.

## External competitor research (self-reported)
PiKa919's public repository reports a 0.661 public score for v20 using a six-backbone LoRA ensemble, an external pool capped/filtered for inference, four-view LinearSVC, ATLAS, and calibrated fusion. These figures are the repository author's claims and are not independently verified here.
The same repository documents negative results: adding many handcrafted dense features overfit; unbalanced external-pool weighting overwhelmed official rows; large sparse matrices caused host-RAM OOM; prompt-centering/assignment can hurt when inferred test groups are small or imperfect.
Its experiment 08 explicitly distinguishes oracle prompt groups from text-inferred deployment groups. Its experiment 09 corpus builder filters for single-paragraph 40–250-word examples and exact model labels, but assigning synthetic sequential prompt IDs to unrelated rows must not be used as genuine prompt grouping.

## Recommended next experiments (one change at a time)
A. **Baseline reproducibility:** run current notebook in diagnostic mode with leaderboard submission disabled; capture exact kernel version, all member status lines, source pool identity/counts, runtime and output row count.
B. **Llama ablation:** run with Llama enabled vs disabled, only after confirming correct base model, adapter, label permutation, and independent validation. Do not assume the published +0.005 gain transfers.
C. **SVC weight sweep:** compare 1.5/3/6/12 using prompt-grouped OOF, and keep the official training rows' class-balanced contribution controlled as external pool size changes.
D. **Pool audit:** cap per class, deduplicate exact and near duplicates, verify source/license/labels, preserve punctuation/case, enforce competition length/paragraph rules. Keep external data auxiliary; never relabel generated text as a genuine target-model sample.
E. **Fusion audit:** evaluate full-pipeline OOF and per-class recall; only then tune weights, offsets, or Sinkhorn.
